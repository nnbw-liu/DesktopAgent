# 插件的技能文件

技能文件是**插件私有的提示词资产**：只在运行该插件时注入 system 消息，不进入全局技能列表。

```markdown
---
name: 翻译
description: 把输入文本翻译成指定语言。
version: 1.0
---

（正文：角色、步骤、约束、输出要求）
```

- frontmatter 可选，但建议保留 `name` / `description` / `version`（设置页与「⋯」菜单展示用）。
- **frontmatter 不会发给模型**，只有正文会。
- 正文里的 `{{key}}` / `{{key.label}}` 会被替换成参数值 / 选项显示名；
  **引用了不存在的参数 = 能力加载失败**（不会静默变空）。
- 用户输入**不会**拼进 skill：宿主把它单独放进 user 消息，并用 `<待处理文本>` 包住
  （输入里的 `<` 会转成全角 `＜`）。所以 skill 里**不要**自己写「用户输入会放在这里」，
  也不要把输入格式写进 system。
- `output.format = segments` 时，宿主自动追加分段格式契约；skill 里**不要**写 `<s>` / `<t>`。

## 写作顺序

1. 先写「你是谁」，再写「按什么步骤」，最后写「禁止什么」。
2. 输出格式写死（「只输出译文，不要解释」），比事后裁剪便宜。
3. 不要要求模型「先分析再输出」——思维链会混进正文。
4. 长度控制在 4 KB 以内，越长的指令越容易被稀释。

## 完整示例：润色

```markdown
---
name: 润色
description: 把文字改得更通顺，不改变原意。
version: 1.0
---

你是一位中文编辑。请润色用户提供的文本。

规则：
- 不改变原意，不增删事实。
- 修正语病、口语化表达与重复用词。
- 保持原有的段落结构与 Markdown 格式。
- 只输出润色后的全文，不要解释改了什么。
```

## 带参数的写法

清单里声明：

```json
"parameters": [
  {
    "key": "tone",
    "label": "语气",
    "kind": "select",
    "default": "neutral",
    "options": [
      { "value": "neutral", "label": "中性" },
      { "value": "formal", "label": "正式" },
      { "value": "casual", "label": "口语" }
    ]
  }
]
```

技能正文里引用：

```markdown
把语气调整为「{{tone.label}}」（代码：{{tone}}）。
```

- `{{tone}}` 是原始值（`neutral`），`{{tone.label}}` 是显示名（`中性`），按需要选一个；
- 模板替换只发生在正文，frontmatter 不参与；
- 同一个参数在正文里可以出现多次。

## 常见反例

| 写法 | 问题 |
| --- | --- |
| `用户输入会放在 <待处理文本> 中` | 宿主负责，写进去反而会和真实定界符冲突 |
| `<s>{{原文}}</s>` | `segments` 的格式由宿主追加；且 `{{原文}}` 未定义会加载失败 |
| `先分析文本结构，再输出结果` | 分析过程会混进最终产物；直接给结果 |
| 引用 `{{lang}}` 但清单里只有 `target` | 占位符未定义 = 能力加载失败 |
| 把大段资料贴进 SKILL.md | 超过 4 KB 容易被稀释；放进技能包的 references 也不适用（插件只认一个 skill 文件） |
| 让插件「读取工作区文件」 | v1 插件没有工具，只有文本输入输出 |
