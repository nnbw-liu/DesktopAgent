# 第一部分：品牌蓝图

## 1. 一句话定位

> **SDemo：一张自己的桌面，上面住着一个会做事的助理。**

不是"又一个待办 App"，也不是"又一个聊天客户端"。是**桌面本身成为一个可被安排的地方**：事情（待办/日程）、资料（文档）、会议（录音与决议）各自有位置，助理能看见它们、能动它们。

三个隐喻对应三块产品：

| 隐喻 | 产品 | 一句话职责 |
| --- | --- | --- |
| 助理 | DesktopAgent | 听懂你要什么，跨应用把事办了 |
| 桌面 | DesktopAssembly | 把工具摆到桌面上，能被看见、能被点 |
| 抽屉 | sdemo.planner / sdemo.kb / sdemo.meeting | 各自管一摊数据，互不越界 |

## 2. 品牌主张（三条，写进产品判断）

1. **事情有归宿**：每一条待办、每一份文档、每一场会议都有确定的存放地与责任人，不散落在聊天记录里。
2. **助理不越权**：AI 能起草、能整理、能提议，但**改你的资料必须先问过你**。
3. **数据在你自己机器上**：默认不出网；唯一出网的是模型调用，且只由助理发起。

## 3. 命名与地址规范（全产品统一）

| 项 | 规则 | 例 |
| --- | --- | --- |
| 应用 id | `sdemo.<domain>` | `sdemo.planner` / `sdemo.kb` / `sdemo.meeting` |
| 实体引用 URI | `sdemo.<app>/<entity>/<id>` | `sdemo.kb/doc/01H…@v3#b2` |
| 单实例互斥量 | `SDemo.App.<appId>` | `SDemo.App.sdemo.planner` |
| 应用数据目录 | `%APPDATA%\SDemo\Apps\<appId>\` | 卸载不删数据 |
| 安装目录 | `%APPDATA%\SDemo\DesktopAssembly\apps\<appId>\` | 程序与数据分离 |
| 运行时文件 | `%LOCALAPPDATA%\SDemo\DesktopAssembly\runtime\` | 端口 / token 不漫游 |
| MCP 端点 | `http://127.0.0.1:{port}/mcp` | 仅回环 + 进程级 token |

## 4. 体验准则（四条，用于裁决"做不做"）

| 准则 | 含义 | 反例（不做） |
| --- | --- | --- |
| 桌面优先 | 常用动作在桌面上一次点击完成 | 为了勾一条待办要打开主窗口 |
| 不阻塞 | 长任务（转写、索引、同步）后台跑，界面永远可操作 | 转写时弹模态进度框 |
| 可撤销 | 任何低风险写入都能撤回 | 批量改完无法回退 |
| 本地优先 | 默认本地，外发必须显式 | 默认开云端同步 |

## 5. 视觉基调

- 组件：半透明、圆角、跟随系统主题与强调色；不抢焦点；可置顶/穿透。
- 密度：桌面上只放"一眼能看完"的东西（≤8 条待办、当前会议计时），细节留在主窗口。
- 语言：简体中文；产品名、工具名、协议名保持原文（如 `todo_accept_draft`）。

## 6. 明确不做（v1）

| 不做 | 原因 |
| --- | --- |
| 团队协作 / 共享清单 | 需要 ACL、冲突裁决、审计，独立立项 |
| 第三方组件 SDK / 组件市场 | 会变成自己造一个操作系统 |
| 云端默认同步 | 违反"本地优先" |
| 与 Outlook / 企业微信日历双向同步 | OAuth + 增量 + 冲突，成本远高于收益 |
| 实时字幕 | 流式 ASR 是另一套工程 |

# 第二部分：产品需求清单

> 编号规则：`<前缀>-<序号>`，优先级 P0（必须）/ P1（应该）/ P2（可选）。
> 本清单只到"需求级"，字段级设计见各产品的设计文档；详细任务拆解等立项。

## A. DesktopAssembly（桌面外壳）

**目标**：常驻托盘，把各应用的组件摆到桌面上，管住进程与窗口，自己不存业务数据。

| # | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| DA-01 | 首次安装扫描 `apps\*`，校验 `app.json` / `widget.json` / exe 哈希 | P0 | 缺文件或哈希不符只影响该组件 |
| DA-02 | 按需拉起应用内核进程，单实例互斥，冷启动显示骨架态 | P0 | 不出现白窗；重复拉起不产生第二个进程 |
| DA-03 | 空闲超时退出（默认 5 分钟），组件关闭不立即杀进程 | P0 | 内存可回收 |
| DA-04 | 崩溃退避重启 3 次后转错误态，组件保留占位卡片 | P0 | 重启后回原位 |
| DA-05 | 跨进程管控 native 窗口：位置、层级、显隐、穿透位 | P0 | 白名单 6 个 Win32 操作，禁止 SetParent |
| DA-06 | 位置与布局持久化（DIP + 显示器标识），多屏拔插后回落 | P0 | 换分辨率不丢布局 |
| DA-07 | 桌面层（`layer=desktop`）仅对 wasm 组件开放 | P1 | native 请求时返回 `HOST_POLICY_DENIED` |
| DA-08 | 组件设置表单按 Schema 子集渲染，不改应用代码 | P1 | 支持 boolean/integer/string(enum) |
| DA-09 | 托盘菜单：显示主窗口、组件诊断、退出 | P1 | 诊断含 pid/端口/最后错误 |
| DA-10 | 快捷键唤起组件（`Ctrl+Alt+T` 等），可改 | P2 | 冲突时提示 |
| DA-11 | 开机自启开关 | P2 | 注册表 Run 项，可关闭 |

**非功能**：常驻内存 ≤ 120MB（不含 WebView2 渲染进程）；自身零磁盘业务数据。
**风险**：Win+D / 最小化拦截行为需实测（P1 首日验证）。

## B. sdemo.planner（待办 + 日历）

**目标**：一张清单加一本日历，AI 能起草，人负责点头。

| # | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| PL-01 | `todo` 与 `event` 同库不同表；todo 可完成，event 有起止 | P0 | 完成率统计不受 event 污染 |
| PL-02 | 待办：标题/备注/截止/优先级/清单/标签 | P0 | — |
| PL-03 | 日程：起止/参与人/地点/关联待办 | P0 | — |
| PL-04 | 日历视图：日/周/月，todo 的 `dueAt` 显示为点 | P0 | 拖拽改期即改 `dueAt` |
| PL-05 | ICS 导出（todo + event） | P0 | 导入系统日历不报错 |
| PL-06 | ICS 只读订阅（URL/本地文件，定时拉取） | P1 | 外部改动可见，不写回 |
| PL-07 | 桌面组件：≤8 条待办 + 快速新增 + 勾选 | P0 | 半透明、不抢焦点、输入框可打字 |
| PL-08 | 提醒：到期前 N 分钟通知 | P1 | 走宿主通知通道 |
| PL-09 | AI 草稿审阅：逐条 采纳/编辑/拒绝 + 疑似重复 | P0 | 草稿不入库 |
| PL-10 | MCP 工具面：`todo_*` / `calendar_*`（见设计文档） | P0 | 删除/批量必须审批 |
| PL-11 | provenance：`source` + 会话 + 原文片段 | P0 | 每条能回答"从哪句话来的" |
| PL-12 | 软删除 + 7 天回收站 + 撤销 | P0 | 误删可恢复 |
| PL-13 | 搜索：标题/备注全文 | P1 | 中文两字可命中 |
| PL-14 | outbox 变更日志，为多端同步预留 | P1 | 导出的 op-log 可被另一端合并 |

**风险**：todo 与 event 合并后模块变大，接口必须按两个实体分开。

## C. sdemo.kb（知识库）

**目标**：个人文档的版本、差异、检索与引用追溯；**不持有模型凭证**。

| # | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| KB-01 | 文档实体 + 版本链（DAG，不可变版本） | P0 | 一次改动只新建一个版本 |
| KB-02 | 块级切分（标题 + 段落），内容寻址去重 | P0 | 改一段不复制整篇 |
| KB-03 | 块级 diff + 词级 diff（Myers/patience） | P0 | 界面能高亮"这一句改了" |
| KB-04 | 变更理由 `rationale`（用户/AI/会议三入口） | P0 | 可回答"为什么改成 D" |
| KB-05 | 命名修订（requirement 强制语义版本） | P1 | v1.0 / v1.1 / v2.0 |
| KB-06 | FTS5 + 2-gram 预分词检索（复用已验证方案） | P0 | 中文两字查询命中 |
| KB-07 | 三个索引面：当前态 / 历史态 / 变更事实 + 查询路由 | P0 | "以前怎么写"能召回历史 |
| KB-08 | 导入 PDF / docx / md，导入即建 `v1` | P0 | 重新导入自动算 diff |
| KB-09 | 引用存 `docId@version#block` | P0 | 能反查受影响的待办 |
| KB-10 | 影响面清单：来源已变更的引用标记 | P1 | 供 DesktopAgent 复核 |
| KB-11 | MCP 工具面 `kb_*`（`kb_update` 高风险必须确认） | P0 | 块级操作，禁止整篇提交 |
| KB-12 | 保留策略：requirement 全留，笔记留 30 版 | P1 | 磁盘占用可见 |
| KB-13 | 向量检索（块级 + 按 hash 复用） | P2 | 改一段只重嵌一段 |

**风险**：索引成本随文档量增长；R2 会把"重索引"变成常态。

## D. sdemo.meeting（会议）

**目标**：录音、转写、议题、决议、待办候选与分析履历，全部本地保存。

| # | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| MT-01 | 采集两种模式：`room`（麦克风）/ `online`（环回 + 麦克风） | P0 | 双路分别转写后按时间合并 |
| MT-02 | 录音存应用数据目录，可导出（m4a/mp3） | P0 | 目录可见、可备份、可清理 |
| MT-03 | 本地 whisper 转写（不出网），模型档位可选 | P0 | 音频零上传；后台可取消 |
| MT-04 | 转写片段：起止毫秒 + 文本 + 置信度 | P0 | 点击跳回录音位置 |
| MT-05 | 说话人：v1 手动标注，**预留自动分离接口** | P0 | 字段 `speaker` + `speaker_source(manual/auto)`；接口 `IDiarizationProvider` 就位，默认空实现 |
| MT-06 | 议题（topic）拆分 + 每议题挂 `refs`（跨项目 URI） | P0 | 一场周会可挂 3 个项目 |
| MT-07 | 决议 `decision`（proposed/confirmed） | P0 | 只有 confirmed 进正式纪要 |
| MT-08 | 待办候选 `action`（candidate/intaken/rejected） | P0 | **不直接创建待办** |
| MT-09 | 分析存档：`model` + `prompt_version`，可重跑并存多版 | P0 | 能对比两次分析差异 |
| MT-10 | 导出 Markdown / JSON 纪要 | P1 | 排版可读 |
| MT-11 | MCP 工具面 `meeting_*` | P0 | `refs` 写入校验存在性 |
| MT-12 | 录音保留策略（90 天 / 永久），占用可见 | P1 | 自动清理前提示 |
| MT-13 | 桌面录音组件（计时 + 结束按钮） | P1 | 半透明、置顶、不抢焦点 |
| MT-14 | 自动说话人分离（diarization 模型接入） | P2 | 接上 `IDiarizationProvider`，`speaker_source=auto` |

**风险**：本地转写耗时（1h ≈ 12–60 分钟）与中文质量；远端录音拾音差。
