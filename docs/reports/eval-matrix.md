## 5. 不可外推的结论

- 云端 DeepSeek V4 Pro 已同配置双跑（7/8 vs 7/8）；本地配置不是纯重复性实验（两轮之间夹了修复）。
- V4.1 Flash 的 **8/8 只有单轮**，且同时换了模型与 P1 工具链，不能把提升单独归因于代码；下一轮 R1 再双跑。
- 8K 配置的 LM Studio 实际加载上下文被模型默认配置覆盖（`lms ps` 显示 162560），Agent 侧仍按 8K 预算裁剪；不要把加载窗口当成评测窗口。
- T05/T06 的测试名检查、T07 的私有方法名检查会放大失败率；行为级任务的表现应单独评估。
- 评测使用自动审批，P7 的“审批 ≤2 次”没有实测；云端 token 成本也没有统计，不能引用为产品指标。
- P7 的 8K 外部仓库目标（≥3/8）未达成；P2 已把 8K 出口改为「本仓库单文件任务 ≥3/5」（P6 4B 实测 3/5），外部仓库 1/8 只作定位能力的参考，不再作为 8K 承诺。
- M4 的 24/24 是「路由命中」：只说明期望工具被暴露、禁用工具未被暴露，不等于 8K 长任务完成率；后者仍以 `tools/AgentEval` 的验收结果为准。

## 6. 8K 口径调整（P2）

| 项 | 旧口径 | 新口径 |
| --- | --- | --- |
| 任务集 | 外部仓库 T01–T08（8 个，多文件 / 测试 / 重构混合） | 本仓库短任务 A–E（A/C/E 单文件；B 跨文件，作为失败样本保留） |
| 出口 | ≥3/8 | ≥3/5 |
| 实测 | 4B 1/8 | 4B 3/5（单轮最差 2/5） |
| 理由 | 8K + 4B 在外部仓库的瓶颈是“定位文件”，不是工具链；把两者混在一个指标里会掩盖真实能力 | 8K 只承诺单文件 / 极短任务；多文件与外部仓库由 32K 档位承担 |

产品侧配合：`workspace_info` 会列出测试项目范围，Full 提示词要求测试类任务先确认测试项目、只改测试文件；这降低“改错文件”，但不改变任务难度。
