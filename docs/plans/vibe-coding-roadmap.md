# Vibe Coding 路线图（2026-10-22 确认版）

> 本文件是总纲。每期任务单独成文（P1–P7），执行时先改本文件的状态表，再动代码。
> 关联：[README](../../README.md) · [插件系统](../plugin-system.md) · [沙箱开发手册](../sandbox-development-manual.md)

## 1. 目标

**一句话**：用户用自然语言提出需求，Agent 在本机仓库里读代码、改代码、跑构建与测试、展示 diff，失败后自我修正，直到验证通过；全程上下文不溢出，所有改动可审阅、可回滚。

判定为「vibe coding 可用」的五个条件：

1. 长会话（50+ 轮）在目标模型上不会因上下文超限失败；
2. 能在真实仓库完成「加一个开关 / 修一个 bug / 补一组测试」这类任务；
3. 编辑以补丁为主，改动有 diff 审阅，误改可撤销；
4. 改完能自己跑构建/测试，单次循环 p50 ≤ 20 秒；
5. 8K 上下文的模型能完成简单任务，且不需要用户手工裁剪历史。

**本周期不做**：多 Agent 编排、LSP / 语义索引、向量库 RAG、云端沙箱、移动端编码、自动提 PR、语法高亮等外围体验。

## 2. 已确认决策（2026-10-22）

| # | 决策 | 结论 | 影响期 |
| --- | --- | --- | --- |
| 1 | 目标形态 | **双模**：大模型完整体验 + 小模型精简模式，共用同一套上下文策略 | P1 / P2 / P6 |
| 2 | 压缩透明度 | **只隐藏不删除**：原文永久保留、可展开、可 pin | P1 / P2 |
| 3 | 摘要模型 | **可配置**，默认同会话模型；失败走确定性兜底 | P2 |
| 4 | 执行安全 | 允许**白名单命令直跑**（不进沙箱、会话级审批、默认关） | P4 |
| 5 | 编辑粒度 | **`apply_patch` 为主**；`write_file` 保留但强制「先读 + 审批」 | P3 |
| 6 | 基准 | 本仓库 3 个任务 + **1 个外部仓库**；先完成任务，再按失败类型优化 | P3–P7 |

## 3. 分期总览

| 期 | 名称 | 目标 | 出口标准 | 人日 | 状态 |
| --- | --- | --- | --- | --- | --- |
| P1 | 上下文预算与硬裁剪 | 所有请求有预算、可计量、不溢出 | 8K 模型 + 200 轮 + 50KB 附件不报 400；计量误差 ≤ 15% | 5 | ✅ |
| P2 | 压缩与工作记忆 | 超预算时增量摘要 + 状态包，只隐藏不删除 | 压缩后 10 问 ≥ 8 对；摘要失败有兜底 | 6 | ✅ |
| P3 | 代码编辑工具链 | 按行读、搜索、补丁、diff 审批 | 本仓库任务 ≤ 12 次工具调用完成，diff 可审 | 4 | ✅ |
| P4 | 内循环提速 | 允许白名单直跑、热沙箱、离线包缓存 | 改→构建→测试 p50 ≤ 20s，审批 ≤ 2 次/任务 | 6 | ✅（4.7 部分 / 4.9 可选未做） |
| P5 | 任务循环与验证门 | todo、验证门、回滚点、循环保护 | 5 个任务 4 个在 15 步内完成且带验证记录 | 3 | ✅（基准 4/5） |
| P6 | 小模型适配 | 档案、短提示、工具裁剪、调用修复 | 8K 模型 5 任务 ≥ 3 完成，峰值 ≤ 90% | 4 | 未开始 |
| P7 | 外部仓库基准与优化 | 真实仓库任务 + 失败分类 + 两轮优化 | 32K ≥ 5/8，8K ≥ 3/8，输出基准报告 | 5 | 未开始 |

合计 **33 人日**，含 20% buffer ≈ **8 周**（单人全职）。

## 4. 依赖关系

```
P1 ──► P2 ──► P3 ──► P4 ──┬──► P5 ──┐
                          │           ├──► P7
                          └──► P6 ────┘
```

- P2 只依赖 P1；P3 只依赖 P1（补丁与上下文无关），但建议按序做，便于复用测试夹具。
- P6 **必须在 P4 之后**：它的评测任务要跑构建/测试，需要 `run_command`。
- P6 与 P5 可以并行（改的文件基本不重叠）；单人执行时按 P5 → P6 串行。
- P7 最后做；它不新增能力，只产出数据和下一轮输入。

## 6. 跨期不变量（架构约束）

1. **单一上下文入口**：所有发给模型的请求只能经 `ContextBuilder`；禁止在 UI、工具或插件里另拼消息列表。
2. **原文只隐藏不删除**：压缩只写摘要、只影响回放；数据库中的消息全文永不因压缩被改写。
3. **默认沙箱**：任何命令默认进沙箱；直跑必须同时满足「白名单 + 显式审批 + 审计」，且默认关闭。
4. **进入上下文的一切都要可估算**：附件、工具结果、技能、提示词都有 token 上限；新增内容必须走预算。
5. **模型无关**：能力差异通过 `ModelProfile` 表达，禁止写 `if (model == "xxx")` 的业务分支。
6. **平台无关代码在 Core**：文件、上下文、摘要、任务循环都在 Core；只有进程执行与沙箱落在 `SDemo.DesktopAgent.Windows`。
7. **每个 PR 带测试**；DB 变更必须同时改 `RequiredColumns` 与迁移测试。
8. **每期一份报告**：`docs/plans/p?-report.md`，含偏差、实测数据、遗留问题（沿用沙箱报告风格）。

## 7. 全局验收指标

基线在 P1 首日测量，写入 `docs/plans/p1-baseline.md`。

| 指标 | 定义 | P1 基线 | M3 目标 | M5 目标 |
| --- | --- | --- | --- | --- |
| 溢出率 | 每 100 轮请求因上下文报错的次数 | 0（13 次真实请求，0 报错） | 0 | 0 |
| 峰值占用 | 单次请求输入 token / 窗口 | 12.0%（短对话 987 / 8192）；8K + 200 轮压测 7.0%（575 / 8192） | ≤ 85% | ≤ 85%（8K 模式 ≤ 90%） |
| 32K 任务成功率 | 8 个基准任务通过数 | 待测（P3+ 才有任务集） | ≥ 50% | ≥ 62%（5/8） |
| 8K 任务成功率 | 同上 | 待测（P3+ 才有任务集） | — | ≥ 37%（3/8） |
| 内循环耗时 | 编辑→构建→测试 p50 | 待测（P4） | ≤ 20s；P4 实测 **6.7s**（build 2.1 + test 4.6，热路径） | ≤ 20s |
| 人工审批 | 每任务审批弹窗次数 | 待测（P4） | ≤ 3；P4 实测 **2 次**（首个 build + 首个 test，之后会话授权） | ≤ 2 |
| 压缩有效率 | 压缩后仍能正确回答早期约束的比例 | 8K 10/10、强制兜底 10/10、32K 10/10（P2 golden） | ≥ 80% | ≥ 80% |

> P1 基线同时记录计量误差：短对话最大 2.28%，8K + 200 轮 + 50KB 附件最大 9.31%，均 ≤ 15%。详见 [p1-baseline.md](p1-baseline.md)。

> 指标是「先测再定」：P1 测完基线后允许调整目标值，但调整必须写进本文件并注明原因。

## 8. 风险登记

| # | 风险 | 影响 | 缓解 | 负责期 |
| --- | --- | --- | --- | --- |
| R1 | MAF 1.25 的工具循环不可拦截 | 中途压缩做不了，长工具轮仍可能爆窗 | P1 先做 0.5 天 spike；退路：`FunctionInvokingChatClient` 迭代上限 + 工具结果强裁 | P1 |
| R2 | 小模型工具调用成功率低 | 能力做了也用不起来 | 工具子集、单工具模式、调用修复、评测矩阵定边界 | P6 |
| R3 | 无网络沙箱与构建冲突 | 内循环起不来 | 白名单直跑（默认关）+ 宿主预 restore + NuGet 缓存映射 | P4 |
| R4 | 摘要丢失用户约束 | 用户不信任、任务跑偏 | pin + 原文保留 + 确定性兜底 + 10 问 golden | P2 |
| R5 | 热沙箱复用导致脏工作区 | 构建结果与真实工作区不一致 | manifest 增量同步 + 外部改动检测 + 会话结束清理 | P4 |
| R6 | 过度压缩导致重复读文件 | 成本与延迟反升 | 压缩目标 60% 而非极限；监控每轮工具调用数 | P2 |
| R7 | prompt cache 被压缩打断 | 成本上升 | 压缩低频批量；稳定前缀放系统+状态，易变内容放尾部 | P1–P2 |

## 10. 执行方式

- **一期一分支**：`feature/vibe-p1-context` … `feature/vibe-p7-benchmark`，每期 2–4 个 PR，PR 之间保持可构建。
- **先测试后接线**：新增服务先写单测（不联网），再接 `AddDesktopAgentCore()` 与 UI。
- **每期首日**：核对上一期报告与本文件状态表；**每期末日**：写 `p?-report.md`，更新状态为 ✅/⚠️，列遗留项。
- **范围变更**：先改本文件（决策 / 分期 / 指标），再改任务文档，最后写代码。
- **不合并未验证的指标**：P7 的通过率必须来自可复现的运行器输出，不能口头估计。
